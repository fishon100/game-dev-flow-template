# 遊戲開發流｜總覽

> 目標：**讓 3～5 個人的小團隊，靠 AI 完成一整個遊戲專案。**
> 做法：人決定「要什麼」和「對不對」，AI 負責「做出來」和「證明做對了」。
> 骨幹：[Spectra](https://github.com/kaochenlong/spectra-app)（規格驅動開發 SDD）＋ 自動測試（測試驅動開發 TDD）。

## 一張圖看懂

```
        人寫、人看、人確認                           AI 讀、AI 做、AI 驗
 ┌──────────── Notion ─────────────┐   同步   ┌──────────── GitHub ─────────────┐
 │ 需求池：企劃丟想法               │ ──────▶ │ Spectra 申請單                   │
 │ 申請單確認：企劃按「同意」        │ ◀────── │  （提案／規則／設計／任務）       │
 │ 試玩回饋：🔴🟡🟢 第 N 輪          │ ──────▶ │ 正式規則 docs/spectra/specs       │
 │ 知識庫：劇情、角色、數值、名詞    │ ──────▶ │ 程式、自動測試、遊戲資料檔        │
 │ 素材進度：美術、音樂的狀態        │ ◀────── │ 素材檔案                          │
 │ 開發日誌、版本狀態（AI 自動寫）   │ ◀────── │ git 紀錄、測試結果、預覽網址      │
 └─────────────────────────────────┘          └─────────────────────────────────┘
                      └──── Obsidian：本機備份（定期匯出兩邊）────┘
```

## 四條原則

1. **需求寫成文件，不靠聊天紀錄。** 聊天會消失（換帳號、換人、換 AI），文件不會。
2. **一個內容只有一個正本。** 人寫的放 Notion，AI 執行的放 GitHub；另一邊只放連結或自動產生的副本。→ [03 Notion 與 GitHub](03%20Notion%20%E8%88%87%20GitHub.md)
3. **改規則一定開申請單。** 不管多小，都走「提案 → 企劃同意 → 實作 → 結案」，這樣每個決定都查得到原因。→ [01 一輪開發](01%20%E4%B8%80%E8%BC%AA%E9%96%8B%E7%99%BC.md)
4. **沒有測試證明，就不算做完。** 能自動判斷對錯的交給測試；「好不好玩」交給人在手機上試玩。→ [04 品質把關](04%20%E5%93%81%E8%B3%AA%E6%8A%8A%E9%97%9C.md)

## 為什麼這樣能少人做完

| 傳統做法要人做的事 | 這套流程 |
|---|---|
| 程式照規格寫程式 | AI 照申請單的任務寫，`/spectra-apply` 可以平行做 |
| QA 每次手動測一遍 | 自動測試每次部署前跑，壞了就擋下 |
| PM 追進度、寫週報 | 申請單的任務勾選就是進度；開發日誌由 AI 結案時寫 |
| 開會對齊需求 | 申請單把「為什麼、改什麼、怎麼驗收」寫清楚，企劃按同意就是對齊 |
| 交接時翻聊天紀錄 | 規則書＋申請單歷史＋開發日誌，新的人（或新的 AI）讀了就能接手 |
