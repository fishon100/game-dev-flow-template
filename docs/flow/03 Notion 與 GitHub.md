# 03 Notion 與 GitHub

> 總覽：[00 總覽](00%20總覽.md)。重點只有一句：**每份內容只有一個正本。** 另一邊只放連結，或由 AI 自動產生的副本。

## 哪些東西放哪邊

| 內容 | 正本在 | 另一邊 | 誰改 |
|---|---|---|---|
| 需求、想法 | Notion「需求池」 | — | 任何人 |
| 申請單（提案／規則／設計／任務） | GitHub `docs/spectra/changes/` | Notion「申請單確認」只放**摘要＋連結＋狀態** | AI 寫，企劃在 Notion 同意 |
| 正式規則書 | GitHub `docs/spectra/specs/` | — | 只能透過申請單改 |
| 試玩回饋 | Notion「回饋」 | 處理後 AI 回填「處理結果」 | 企劃寫，AI 回填 |
| 劇情、角色、名詞、世界觀 | Notion「知識庫」 | GitHub 遊戲資料檔（AI 同步產生，不要手改） | 劇本 |
| 數值表、關卡表 | 試算表（匯出到 `tools/tables/in/`） | GitHub 遊戲資料檔（AI 同步產生） | 數值／企劃 |
| 手感數值 | GitHub `web/tuning.json` | Notion 知識庫「數值總表」放連結 | 數值（用調參面板） |
| 美術設計稿 | Figma | Notion「素材」放 Figma 連結 | 美術 |
| 素材檔（遊戲讀的圖、聲音） | GitHub `web/assets/` | Notion「素材」記狀態 | 美術匯出，AI 放進遊戲 |
| 開發日誌、版本狀態 | Notion「開發日誌」 | GitHub 的 git 紀錄 | AI 結案時寫 |
| 這套開發流 | GitHub `docs/flow/` | Notion 放一份給人讀（AI 同步） | 程式／企劃透過 PR |
| 本機備份 | — | Obsidian（`tools/backup-obsidian.ps1`） | 自動 |

## Notion 工作區結構

```
🎮 <遊戲名>（專案首頁：一句話、預覽網址、目前版本、本週在做什麼）
├─ 📘 主架構規劃書        ← 頁面：一句話、設計支柱、核心循環、核心規則（不能改的）
├─ 💡 需求池              ← 資料庫
├─ ✅ 申請單確認          ← 資料庫（看板檢視：依「狀態」分欄）
├─ 🎮 回饋                ← 資料庫
├─ 📚 知識庫              ← 資料庫（劇情、角色、名詞、數值、世界觀、美術風格指南）
├─ 🎨 素材                ← 資料庫
├─ 📒 開發日誌            ← 資料庫
└─ 📖 開發流說明          ← docs/flow 的副本（不要在這裡改）
```

### 資料庫欄位

**💡 需求池**
| 欄位 | 類型 | 說明 |
|---|---|---|
| 標題 | 標題 | 一句話：玩家想要什麼 |
| 說明 | 內文 | 遇到什麼問題、想要什麼感覺、參考圖 |
| 優先 | 選項 | 🔴 必做／🟡 想做／⚪ 之後 |
| 提出人 | 人員 | |
| 狀態 | 選項 | 新想法／討論中／已開申請單／不做 |
| 申請單 | 關聯 → 申請單確認 | 開單後 AI 自動連上 |

**✅ 申請單確認**
| 欄位 | 類型 | 說明 |
|---|---|---|
| 名稱 | 標題 | 申請單代號（例 `item-capsules`） |
| 中文標題 | 文字 | 一句話說這張在做什麼 |
| 狀態 | 選項 | 提案中／**待同意**／實作中／待試玩／已結案／退回 |
| 摘要 | 內文 | AI 從 proposal.md 整理：為什麼、改什麼、BREAKING、**需要企劃確認的事** |
| 任務進度 | 文字 | 例「8/8」，AI 更新 |
| 影響功能 | 多選 | 對應規則書的功能代號 |
| GitHub | 網址 | 申請單資料夾連結 |
| 預覽 | 網址 | 上線後的試玩連結 |
| 來源 | 關聯 → 需求池／回饋 | |
| 企劃意見 | 文字 | 退回或要調整時寫這裡 |

**🎮 回饋**
| 欄位 | 類型 | 說明 |
|---|---|---|
| 標題 | 標題 | 一句話描述問題 |
| 等級 | 選項 | 🔴 必修／🟡 建議／🟢 很好（AI 保留不動） |
| 輪次 | 數字 | 第幾輪試玩 |
| 版本 | 文字 | 試玩的版本（通知裡有） |
| 說明 | 內文 | 截圖直接貼 |
| 狀態 | 選項 | 新回饋／處理中／已處理／不處理 |
| 處理結果 | 文字 | AI 回填：改了什麼、哪張申請單、數據 |
| 申請單 | 關聯 → 申請單確認 | |

**📚 知識庫**
| 欄位 | 類型 | 說明 |
|---|---|---|
| 標題 | 標題 | 例「角色－阿鰭」「劇情腳本－第 1 區」 |
| 類別 | 選項 | 劇情／角色／名詞／數值／世界觀／美術風格 |
| 遊戲裡的位置 | 文字 | 同步到哪個檔案（AI 第一次同步時填） |
| 最後同步 | 日期 | AI 同步後更新；比「最後編輯」早＝還沒同步 |

**🎨 素材**
| 欄位 | 類型 | 說明 |
|---|---|---|
| 檔名 | 標題 | `物件_狀態.png` |
| 類別 | 選項 | 角色／場景／UI／特效／音樂／音效 |
| 狀態 | 選項 | 待製作／方向稿／精修中／完成／已放進遊戲 |
| 規格 | 文字 | 尺寸、格式、長度 |
| 使用位置 | 文字 | 遊戲裡哪個畫面 |
| Figma | 網址 | |
| 提示詞 | 文字 | 出方向稿用的 AI 提示詞 |
| 負責人 | 人員 | |

**📒 開發日誌**
| 欄位 | 類型 | 說明 |
|---|---|---|
| 標題 | 標題 | 「v3.7.1 道具改成掉落膠囊」 |
| 日期 | 日期 | |
| 版本 | 文字 | |
| 類型 | 選項 | 申請單結案／修 bug／同步／自主優化 |
| 內容 | 內文 | 回饋 → 改了什麼 → 數據 → 驗收 |
| 申請單 | 關聯 → 申請單確認 | |

## 同步的方向與時機

| 對 AI 說 | 方向 | AI 做什麼 |
|---|---|---|
| 「看需求」 | Notion → GitHub | 讀需求池「新想法」，整理後問你要開哪幾張 |
| 「把 <需求> 開成申請單」 | GitHub → Notion | 寫申請單，在「申請單確認」建卡（狀態：待同意） |
| 「看申請單」 | Notion → GitHub | 讀「待同意」卡片的狀態與企劃意見，同意的就開始做 |
| 「看回饋」 | Notion → GitHub | 讀「新回饋」，開申請單或直接修，回填處理結果 |
| 「同步 <知識庫頁面>」 | Notion → GitHub | 轉成遊戲資料檔、跑測試、部署，更新「最後同步」 |
| 「<名稱> 結案」 | GitHub → Notion | 規則併回、申請單卡改「已結案」、開發日誌寫一筆 |
| 「更新專案首頁」 | GitHub → Notion | 版本、預覽網址、本週進度 |
| 「同步開發流」 | GitHub → Notion | `docs/flow/` 覆蓋 Notion「開發流說明」 |
| 「備份」 | 兩邊 → Obsidian | 執行 `tools/backup-obsidian.ps1`，並把 Notion 頁面匯出成 Markdown |

> Notion 的頁面與資料庫 ID 記在 `docs/notion.json`（新專案第一次建 Notion 時由 AI 填寫）。

## 為什麼不全部放 Notion 或全部放 GitHub

- **全部 GitHub**：企劃、美術、劇本要學 git 和 Markdown，門檻太高
- **全部 Notion**：AI 不能在 Notion 裡跑測試、部署，規則書和程式會對不上
- 所以：**人寫的在 Notion，AI 要執行的在 GitHub，中間靠固定的「同步」指令**
