# 02 角色分工

> 總覽：[00 總覽](00%20總覽.md)。原則：**每個人用自己熟悉的工具，交付到固定的地方；AI 負責轉成遊戲能用的檔案。**
> 小團隊常常一人兼多職，下面是「職能」，不是「人數」。**除了程式審查，其他角色都不需要碰 git 或程式。**

## 一覽

| 職能 | 每天打開 | 交付什麼 | 要確認什麼 |
|---|---|---|---|
| 🎯 企劃（兼 PM） | **🧭 工作台**（手機或電腦） | 需求、主架構規劃書、試玩回饋 | 每張提案（同意／留言）、每次上線（試玩） |
| 🎨 美術 | Figma ＋ 工作台 | 風格指南、角色設定、素材檔 | 遊戲裡的畫面是否符合設計稿 |
| 📖📊 劇本／數值 | Notion 知識庫（或 repo 的 `docs/企劃/`）＋試算表 | 劇情腳本、角色卡、名詞表、數值表、關卡表 | 同步後遊戲裡的文字與數值 |
| 💻 程式（審查把關） | GitHub ＋ Spectra 桌面版 ＋ Claude Code | 架構決定、審查意見、**技術提案** | 提案的 design、AI 寫的程式、測試有沒有測到重點 |

## 🎯 企劃（兼 PM）

**每天 5 分鐘（手機就可以）**
1. 打開工作台，看首頁「**需要你處理**」
2. 有「等你同意」→ 點「看內容並同意」→ 讀為什麼、改什麼、**需要企劃確認的事** → 勾 ☐ 企劃同意（或留言）
3. 有「做完了」→ 點「試玩」玩一下 → 沒問題對 AI 說「<名稱> 驗收通過」；有問題按「寫回饋」
4. 新想法 → 「提需求」

**寫需求的訣竅**
- 寫「玩家遇到什麼、想要什麼感覺」，不用寫怎麼做
- 用名詞表的名字（例：「彈跳柱」而不是「中間那個柱子」）——AI 最怕名詞不清楚
- 附參考圖、參考遊戲；能量化就量化（「第 1 區新手每關最多掉 1 顆愛心」）

**PM 的部分**
- 進度＝工作台的「提案」分頁（待同意／已同意／製作中／待驗收／已完成＋進度條）
- 品質＝工作台「上線紀錄」（自動測試與部署有沒有成功）
- 週報＝開發日誌（AI 驗收時自動寫）

## 🎨 美術

1. 在知識庫「美術風格指南」寫方向（關鍵字、參考圖、色票）
2. 對 AI 說「出 <角色／場景> 方向稿」→ AI 依風格指南寫提示詞，用圖像 AI 出幾張方向稿
3. 挑選後在 **Figma** 精修；完成的素材交給 AI（貼 Figma 連結或把檔案放到雲端硬碟）
4. 對 AI 說「換上 <素材>」→ AI 放進 `web/assets/`、接進遊戲、部署
5. 素材進度記在 Notion「素材」（或知識庫的素材清單）

> 沒有正式素材前，AI 會用程式畫的占位圖，玩法不用等美術。

## 📖📊 劇本／數值

**劇本**：在 Notion「知識庫」（或 `docs/企劃/知識庫/`）寫劇情腳本、角色卡；寫完對 AI 說「同步 <頁面名稱>」，AI 會轉成遊戲資料檔、跑文字長度等測試、部署。

**數值**
- 手感數值（速度、重力…）：只存在 `web/tuning.json`。專案有做遊戲內調參面板的話可以邊玩邊調，滿意後說「套用調參」
- 大量表格（關卡、道具、敵人）：用 Google 試算表或 Excel，匯出 `.xlsx` 或 `.csv` 交給 AI（放到 `tools/tables/in/`），說「同步 <表名>」
- 難度：說「量一下第 N 關難度」，AI 用擬人玩家跑幾十局回報（[04 品質把關](04%20品質把關.md)）

## 💻 程式（審查把關）

人不用寫大部分程式，但要把關這幾件事：
1. **提案的 design.md**：做法會不會讓之後很難改？有沒有更簡單的？
2. **`/spectra-review` 報告**：AI 程式審查的結果，決定哪些要修
3. **測試**：測試有沒有真的測到規則（改壞時會不會失敗）
4. **技術提案**：重構、效能、工具、測試、建置這類「玩家看不到」的改動，由程式提出（或 AI 提出）、**程式同意**；做完會開 PR，**程式審查合併**後才上線。企劃提案照樣由企劃同意、測試過就上線，不用等程式

完整做法（環境、每天的流程、審查清單）→ [09 程式：用 Spectra 開發](09%20程式：用%20Spectra%20開發.md)

另外負責：repo 設定、GitHub Actions（部署、工作台）、部署失敗時排查、決定什麼時候換正式引擎（例如網頁原型 → Godot／Unity）。
**Spectra 桌面版**最適合這個角色：一次看所有提案的說明、規則差異、設計、任務，並可以直接勾同意、暫存（park）、驗收。

## 交接

任何角色換人，新的人讀這三樣就能接手：
1. 工作台（現在在做什麼、等誰）
2. `docs/flow/`（這套流程）＋ `docs/spectra/specs/`（遊戲現在的規則）＋ 開發日誌
3. [05 工具與帳號](05%20工具與帳號.md) 的帳號表與「換電腦／換人清單」
